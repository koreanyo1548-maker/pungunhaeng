# 상태·스킬·리소스 리팩토링

기준은 일반 NPC/객잔/조각 연결이 포함된 `9bafabe`다. PR #13 위에 쌓는 변경이며, 화면 배치·저장 스키마·게임 규칙은 유지한다.

## 변경

- 최고 점수는 `profile.best` 한 곳에서 읽고 기록한다. 저장 코드 불러오기 직후 표시가 갱신되고, 이후 낮은 점수로 종료해도 불러온 기록을 덮어쓰지 않는다.
- 이벤트형/주기형 스킬은 각각의 발동 조건을 유지하면서 `executeSkill`의 같은 실행·강화 절차를 따른다. 기술 소유 조회는 `skill-state.ts`, 동기식 발사체/연출 소유 문맥은 `core/skill-context.ts`로 분리했다. 후자는 중첩 호출과 예외에서도 `finally`로 원래 문맥에 복귀한다.
- 전역 `G: any`를 제거하고 핵심 시뮬레이션 모델 `RunState`, `Player`, `Shot`, `Enemy`를 명시했다. 이벤트 데이터/표현 효과/위험물·아이템 일부는 여전히 점진적 타입 보완 대상이다. 전체 strict 전환은 하지 않는다.
- 새 판 상태·플레이어·일시적 컬렉션의 생성은 `core/run-state.ts`에서 맡는다. 메타 스냅샷과 최초 난수 호출 시점은 그대로다. 영구 프로필·이미지 캐시·스크롤처럼 원래 재시작에서 보존하던 값은 유지한다. 입력과 UI, 렌더러 소유 효과의 초기화는 각 소유 모듈에 남긴다.
- 이미지 디코딩/크롭 함수는 `core/image.ts`, 기술 시트 로딩/측정된 프레임 보정은 `assets/skill-art.ts`로 이동했다. 동일 URL의 디코딩 Promise를 공유하고 실패 시 캐시에서 제거하여 재시도를 허용한다. 일반 NPC 로더도 공통 도구를 사용한다. 곧바로 덮어쓰던 구형 fx.png 로딩·프레임 생성과 미사용 manifest 항목은 제거했다. 원본 파일은 유지한다.
- 전투 업데이트는 플레이어 → 관문 → 기술 → 발사체 → 적 → 위험물 → 아이템 → 정리/HUD의 원래 순서로 유지하며 각 처리를 작은 함수로 나눴다. 장면 전환으로 중단되는 경로도 그대로다.

## 검증

- 기존 `npm test`, `npm run test:ui`, 일반/단일 파일 빌드.
- `node tests/e2e/refactor-regressions.mjs`: 실제 저장 코드 UI로 높은 기록을 불러오기, 낮은/높은 판 종료 후 저장과 화면 확인, 중첩 스킬 문맥의 예외 복구, 실제 재시작의 상태와 효과 초기화.
- `node tests/e2e/skill-art.mjs`: 일반/동작 줄이기에서 24개 기술, 3개 보스 조합, 영웅 등장과 무효 발동/소진/초기화.
- 이전 HTML과 24개 기술을 장착한 같은 시드·입력의 두 코스 비교. `tests/equivalence/combat-layout.mjs`로 세 화면 크기의 전투 배치 비교.

## 남은 경계

전체 순환 의존성을 없앤 재설계는 아니다. 기술 정의에 실행 콜백이 들어 있는 구조와 일부 게임/화면 모듈의 상호 참조는 남아 있다. 이번에는 순수 소유 조회와 연출 문맥, 이미지 로딩을 별도 모듈로 꺼내고 실제 중복·오류부터 줄였다. 추가 분리는 기능 변화와 섞지 않고 같은 회귀 검사를 사용한다.
