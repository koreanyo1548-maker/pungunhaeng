# 메타 성장 계획

상태: **M0(저장 기반·정산)과 M1(수련) 구현 완료. M2 이후는 제안.** 판과 판 사이에 남는 성장 세 가지를 넣는다: 영웅 수집, 인연 카드, 엽전으로 올리는 기본 능력치. 용어는 [화면 용어](terms.md)를 따른다.

## 0. 구현된 것 (M0, M1, M2)

10장의 결정 사항은 추천안으로 진행했다: 탈락해도 엽전 전액 보관, 저장 코드로 이어가기. 영웅과 난이도 관련 결정은 M2, M4에서 다시 확인한다.

- `core/profile.ts`: 프로필 저장(`localStorage`의 `pungun-profile`), 손상된 저장 복구(`sanitize`), 이전 최고 점수 옮기기, 저장 코드 내보내기·가져오기.
- `data/meta.ts`: 능력치 6종의 효과와 가격(5장의 표 그대로), 완주 보너스 300냥, 정산 계산(`settle`).
- 판 시작 시 `G.state.meta`에 스냅샷을 복사한다. 판 안에서는 이 값만 읽는다. 연결 지점: 시작 체력·필살기(`flow.ts`), 공격력(`shotPower`), 필살기 충전(`gainCharge`), 교체 대기(`swapCooldown`).
- 판이 끝나면 남은 엽전을 보관하고 결과 화면에 정산 줄을 보여 준다.
- `scenes/training.ts`: 수련 화면. 타이틀의 "수련" 버튼과 결과 화면의 "수련하러 가기"로 연다.
- 디버그 훅 `window.__g.profile`, `window.__g.loadProfile(...)`.
- 검증: E2E 시나리오 E(보관 → 구매 → 다음 판 반영, 저장 코드, 손상된 저장 복구, 판 도중 스냅샷 유지). 빈 프로필에서 이전 빌드와 시드 비교 4건 IDENTICAL, 전투 배치 3해상도 IDENTICAL.

### M2 영웅 수집

3장의 추천안 그대로다: 시작 영웅 풍운객·비천, 나머지 4명은 조건 달성으로 합류, 숙련 ★1~5.

- `data/meta.ts`: 시작 영웅(`STARTERS`), 합류 조건과 진행도(`UNLOCKS`), 숙련 단계(`MASTERY_STEPS` 0/3/8/15/25).
- 프로필에 영웅별 `owned`·`mastery`와 기록(`records`: 길별 돌파한 관문, 완주 횟수, 스침 누적)을 저장한다. 기록이 이미 조건을 채운 저장은 불러올 때 그 영웅을 합류시킨다.
- `systems/meta.ts`: 관문을 돌파하면(`gateCleared`) 편대의 두 영웅 숙련 +1, 길 기록 갱신, 합류 확인. 판이 끝나면(`runEnded`) 스침을 누적한다. 판 안의 계산은 여전히 시작 시 스냅샷(`G.state.meta.heroes`)만 읽으므로, 판 도중에 숙련이 올라도 그 판은 바뀌지 않는다.
- 특성 수치는 `systems/formation.ts`의 `traitPower`·`traitCharge`·`traitGraze`·`traitFire`·`traitNearCharge`가 숙련 단계를 읽어 계산한다. 교체 기술은 `fx(m, 단계)`로 강해진다. 단계 0의 값은 이전 상수와 같다.
- 편대 편성: 합류한 영웅이 앞에 오고, 잠긴 영웅은 어둡게 "잠김"으로 보인다. 눌러서 합류 조건과 진행도를 미리 볼 수 있고, 선택 버튼은 눌리지 않는다.
- 합류 알림: 전투 중 알림 글자, 바로 다음 선택 화면 위쪽의 "새 영웅 합류" 줄, 결과 화면 정산 줄.
- `scenes/roster.ts`: 타이틀의 "영웅" 버튼으로 여는 목록. 합류한 영웅의 숙련과 지금 특성 수치, 잠긴 영웅의 합류 조건과 진행도를 보여 준다.
- 디버그 `#debug&roster`: 모든 영웅이 합류한 상태로 시작한다. 기존 E2E와 시드 비교가 이 표시를 쓰므로 이전 빌드와 결과를 그대로 비교할 수 있다. 테스트에서 기본 명단으로 열려면 `openGame(file, { roster: false })`.
- 검증: E2E 시나리오 F(시작 2명, 잠긴 영웅은 미리보기만, 관문 2 돌파로 철혈 합류, 완주로 홍련 합류, 다음 판에 숙련 단계 반영, 스침 300으로 묵영 합류, 저장 복구). `&roster`로 main 빌드와 시드 비교 3건 IDENTICAL, 전투 배치 3해상도 IDENTICAL.
- 남은 것: 교체 기술 설명 문구는 숙련 단계에 따라 바뀌지 않는다(효과만 강해진다). 묵영·운학처럼 시작 영웅이 없는 역할은 합류 전까지 고를 수 없으므로 초반 난이도는 M4 밸런스 검토에서 본다.

## 1. 지금 코드에서 확인한 것

| 항목 | 현재 상태 | 위치 |
|---|---|---|
| 저장 | 최고 점수 하나만 저장한다(`localStorage`의 `wuxia-best`) | `core/context.ts`, `systems/flow.ts` `end()` |
| 영웅 | 6명(땅 3, 하늘 3)이 처음부터 모두 열려 있다. 특성 수치는 공용 상수다 | `data/heroes.ts`, `data/tune.ts`의 `trait*`, `systems/formation.ts` `traitOn` |
| 인연 | 6명. 각자 고유 기술 하나를 가진다. 한 판 안에서 호감도 2가 되어야 전수받는다 | `data/npcs.ts`의 `unique`, `TUNE.sasaRel`, `scenes/dono.ts` |
| 엽전 | 판 안에서만 쓴다(객잔). 판이 끝나면 남은 엽전은 결과 화면에 숫자로만 나오고 사라진다 | `entities/pickups.ts`, `scenes/inn.ts`, `flow.ts` `end()` |
| 엽전 수입 | 관문 하나에 약 330냥. 객잔에서 안 쓰고 완주하면 약 1,300냥. 보스 기술 대신 엽전을 고르면 +250냥 | 밸런스 봇 측정 |
| 기본 능력치 | 체력 3, 필살기 2회(최대 3회), 공격력 기준 1.3, 교체 대기 6초 | `flow.ts` `start()`, `combat.ts` `shotPower`, `TUNE.swapCd` |
| 판 흐름 | 타이틀 → 길 → 편대(출전·대기) → 인연 → 관문 … → 결과. 순서는 한 파일에서 정한다 | `systems/scene-flow.ts` |
| 선택 화면 | 카드 목록, 비활성 카드, 가격 표시를 이미 지원한다 | `scenes/choice.ts`, `scenes/inn.ts` |

고유 기술은 지금 얻기가 매우 어렵다. 관문은 세 개뿐이고, 의뢰를 따라서 성공하면 다른 인연에게 소개된다(`NPC_LINK`). 호감도 2를 만들려면 맞수를 거슬러 성공한 다음 그 인연을 따라 성공하거나, 객잔의 수소문으로 같은 인연을 다시 만나야 한다. 인연 카드가 이 문제를 푸는 자리다.

## 2. 공통 기반

### 2.1 저장 (`core/profile.ts` 신설)

```ts
type Profile = {
  v: 1;
  coins: number;                                  // 보관한 엽전
  stats: Record<StatId, number>;                  // 능력치 단계
  heroes: Record<HeroId, { owned: boolean; mastery: number }>;
  cards: Record<NpcId, { copies: number }>;       // 인연 카드 조각 누적 (단계는 여기서 계산)
  records: { best: number; clears: Record<'ground' | 'sky', number>; firsts: string[] };
};
```

- `localStorage` 키 하나(`pungun-profile`)에 JSON으로 저장한다. 읽기·쓰기는 모두 `try/catch`로 감싸고, 실패하면 기본값으로 동작한다.
- 기존 `wuxia-best`는 처음 읽을 때 `records.best`로 옮긴다.
- **저장 코드 내보내기·가져오기**를 넣는다. 단일 HTML 파일을 폰에서 직접 열면 파일 이름이나 여는 방식이 바뀔 때 저장이 이어지지 않을 수 있기 때문이다(9장 참고).

### 2.2 판 시작 시 스냅샷 (결정론 유지)

- `start()`에서 프로필을 읽어 `G.state.meta`에 복사한다. 판 안의 모든 계산은 `G.state.meta`만 읽는다.
- 같은 시드와 같은 스냅샷이면 같은 판이 재현된다. 연출용 난수와 게임용 난수 분리 원칙은 그대로다.
- **빈 프로필은 지금 게임과 완전히 같아야 한다.** 테스트 브라우저는 저장이 비어 있으므로 기존 E2E와 시드 비교 테스트가 그대로 회귀 검사가 된다.
- 디버그 훅 `window.__g.setMeta(...)`와 URL `#meta=`로 스냅샷을 강제할 수 있게 한다(테스트, 밸런스 봇용).

### 2.3 강호 정비 화면 (허브)

- 타이틀 화면에 보관 엽전과 버튼 세 개를 더한다: **영웅**, **인연첩**, **수련**. 기존 선택 화면(`openChoice`)을 재사용한다.
- 결과 화면에 **정산** 줄을 더한다: 남은 엽전, 새로 얻은 인연 카드 조각, 해금된 영웅. "수련하러 가기" 버튼으로 바로 이어진다.
- 전투 HUD와 전투 배치는 건드리지 않는다.
- 한 화면은 한 가지만 묻는다. 수치 나열 대신 "지금 → 다음 단계"만 보여 준다.

## 3. 영웅 수집

### 3.1 방식

- 시작 영웅 2명: **풍운객(땅)**, **비천(하늘)**. 두 길 모두 적성이 맞는 영웅이 한 명씩 있게 한다.
- 나머지 4명은 **조건을 달성하면 해금**한다(추천). 조건이 분명하고, 뽑기용 재화를 따로 만들지 않아도 된다.

| 영웅 | 해금 조건 (초안) | 의도 |
|---|---|---|
| 철혈 | 땅의 길 관문 2 처음 돌파 | 첫 목표. 한두 판 안에 얻는다 |
| 운학 | 하늘의 길 관문 2 처음 돌파 | 하늘 길로 유도 |
| 묵영 | 스침 누적 300회 | 회피 플레이 보상 |
| 홍련 | 어느 길이든 처음 완주 | 완주 보상 |

- 편대 편성 화면에서 잠긴 영웅은 흐리게 보이고, 카드에 해금 조건과 진행도를 적는다. 기존 `heroCard`의 비활성 상태를 쓴다.
- 해금 순간은 결과 화면 정산에서 영웅 그림과 함께 알린다.

### 3.2 영웅 성장: 숙련도

- 편대에 넣고 관문을 돌파할 때마다 그 영웅의 숙련도가 1 오른다. 재화를 따로 만들지 않는다.
- 숙련 단계는 ★ 1~5(누적 0/3/8/15/25). 기술 등급과 같은 표기를 쓴다.
- 단계가 오르면 그 영웅의 **특성**과 **교체 기술**이 강해진다.

| 영웅 | 특성 (★1 → ★5) | 교체 기술 |
|---|---|---|
| 풍운객 | 근접 처치 시 필살기 충전 +5 → +9 | 검강 위력 +10%씩 |
| 철혈·비천 | 공격력 +25% → +41% | 위력 +10%씩 |
| 묵영 | 스침 판정 +40% → +60% | 무적 시간 +0.1초씩 |
| 운학 | 필살기 충전 +40% → +60% | 충전량 +5씩 |
| 홍련 | 기본 공격 속도 +20% → +32% | 비도 +1자루씩 |

- 구현: `TUNE.traitPower` 같은 공용 상수를 `traitValue(heroId)` 함수로 바꾼다. 함수는 `G.state.meta.heroes[id]`의 단계를 읽는다. 교체 기술 `fx(m)`에는 단계 보정을 곱한다.

## 4. 인연 카드

### 4.1 카드와 조각

- 인연 6명마다 카드 한 장. 카드는 그 인연의 **고유 기술**을 강화한다.
- 조각을 얻는 때 (한 판 안의 호감도 규칙과 같은 방향이다):
  - 의뢰를 **따라서 성공**: 그 인연 조각 +1
  - 의뢰를 **거슬러서 성공**: 그 인연의 맞수 조각 +1
  - 최종 관문 돌파: 도와준 인연마다 조각 +1
- 카드 단계는 누적 조각으로 정한다: 1단계 1개, 2단계 3개, 3단계 6개, 4단계 10개, 5단계 15개.
- 원화는 기존 인연 초상을 쓴다. 새 그림 없이 시작할 수 있다.

### 4.2 단계별 효과

| 단계 | 효과 |
|---|---|
| 1 | 인연첩에 등록 |
| 2 | 고유 기술 강화 I |
| 3 | **전수 조건 완화**: 그 인연의 의뢰를 한 번만 따라서 성공해도 고유 기술을 전수받는다 (필요 호감도 2 → 1) |
| 4 | 고유 기술 강화 II |
| 5 | 최종 관문에서 그 인연의 도움이 강해진다 (낙검 위력 10 → 14) |

3단계가 가장 큰 변화다. 지금은 거의 볼 수 없는 고유 기술을 실제로 쓰게 된다.

| 인연 | 고유 기술 | 강화 I | 강화 II |
|---|---|---|---|
| 청운 도인 | 태극운검 | 되돌린 탄 위력 3 → 4 | 탄을 두 발로 되돌림 |
| 혈마 밀사 | 혈마해방 | 무아지경 2초 → 2.5초 | 3초 |
| 철벽 노승 | 금강부동 | 충격파 범위 140 → 165 | 무적 0.45초 → 0.65초 |
| 비연 낭자 | 만천화우 | 비도 3자루 → 4자루 | 5자루 |
| 떠돌이 약선 | 회춘단 | 막은 뒤 무적 1.3초 → 2초 | 관문마다 2회 막음 |
| 녹림 의적 | 의협난도 | 도기 위력 5 → 6 | 5방향 → 7방향 |

- 구현: `data/skills.ts`의 고유 기술이 `cardLevel(npcId)`를 읽어 수치를 정한다. 카드 문구(`effect`)도 단계에 맞춰 만든다. `scenes/dono.ts`의 전수 조건은 `TUNE.sasaRel` 대신 인연별 값을 쓴다. 최종 관문 도움은 `abilities.ts`의 낙검 위력에 반영한다.
- 기술 선택 카드에는 "인연 카드 3단계"처럼 한 줄만 덧붙인다.

## 5. 기본 능력치 (엽전)

### 5.1 엽전 정산

- 판이 끝나면 남은 엽전을 보관 엽전에 더한다. 완주든 중도 탈락이든 **전액** 보관한다(추천). 완주하면 300냥을 더 준다.
- 판 안의 선택이 메타와 이어진다: 객잔에서 쓸지 남길지, 보스 기술 대신 엽전 250냥을 고를지. 지금은 약했던 엽전 선택지에 의미가 생긴다.

### 5.2 능력치

| 능력치 | 효과 | 최대 | 연결 지점 |
|---|---|---|---|
| 체력 | 시작 체력 +1 | 2단계 (3 → 5) | `flow.ts` `start()` |
| 공격력 | 기본 공격과 기술 위력 +4% | 10단계 (+40%) | `combat.ts` `shotPower` |
| 필살기 충전 | 충전량 +5% | 6단계 (+30%) | `combat.ts` `gainCharge` |
| 필살기 준비 | 시작 필살기 +1회 | 1단계 (2 → 3) | `flow.ts` `start()` |
| 교체 숙련 | 교체 대기 -0.5초 | 2단계 (6 → 5초) | `TUNE.swapCd` 사용처 |
| 재물운 | 정산 엽전 +5% | 6단계 (+30%) | 정산 계산 |

- 재물운은 판 안의 엽전이 아니라 정산에만 곱한다. 객잔 가격과 판 안의 경제는 그대로 둔다.

### 5.3 가격 초안

수입 기준: 초반 탈락 약 300냥, 완주 약 1,300~1,800냥.

| 능력치 | 가격 (단계별) | 전부 올리는 데 |
|---|---|---|
| 공격력 | 200, 300, 450, 650, 900, 1200, 1600, 2100, 2700, 3400 | 13,500 |
| 필살기 충전 | 250, 400, 650, 1000, 1500, 2200 | 6,000 |
| 재물운 | 300, 500, 800, 1200, 1800, 2600 | 7,200 |
| 체력 | 1,500, 4,000 | 5,500 |
| 필살기 준비 | 2,000 | 2,000 |
| 교체 숙련 | 800, 1,800 | 2,600 |

- 첫 판이 끝나면 공격력 1단계를 살 수 있다. 전부 올리려면 약 36,800냥, 완주 기준 25판 안팎이다.
- 수치는 `data/meta.ts` 한 파일에 모아 두고, 밸런스 봇에 프로필을 넣어 관문별 시간과 완주율을 보며 조정한다.

## 6. 밸런스

- 능력치를 다 올리면 지금 난이도는 쉬워진다. 최근에 기술 위력을 올리고 보스 체력을 1.5배로 맞춘 것처럼, 메타 성장에 맞는 상대가 필요하다.
- 제안: 완주하면 열리는 **난이도 단계**를 둔다(예: 강호 → 절정 → 화경). 적 체력과 탄 속도에 배율을 주고, 정산 엽전과 조각을 더 준다. `difficulty()`에 단계 배율을 더하면 된다.
- 이 항목은 마지막 단계로 미루고, 앞 단계에서는 "얼마나 쉬워지는지"를 측정만 한다.

## 7. 구현 순서

각 단계는 별도 PR이다. 빈 프로필에서 게임 진행이 이전과 같은지 매 단계 확인한다.

| 단계 | 내용 | 게임 변화 |
|---|---|---|
| **M0 기반** | `profile.ts`(저장, 옮기기, 내보내기·가져오기), 판 시작 스냅샷, 디버그 훅, 타이틀 허브 뼈대, 결과 정산 줄 | 엽전이 보관되기 시작한다. 쓸 곳은 아직 없다 |
| **M1 수련** | 능력치 6종, 수련 화면, 가격표 | 엽전으로 영구 강화 |
| **M2 영웅 수집** | 해금 조건, 편성 화면의 잠금 표시, 해금 알림, 숙련도와 특성 단계 | 시작 영웅 2명, 나머지는 해금 |
| **M3 인연 카드** | 조각 획득, 카드 단계, 고유 기술 강화표, 전수 조건 완화, 인연첩 화면 | 고유 기술이 실제 선택지가 된다 |
| **M4 난이도** | 난이도 단계, 보상 배율, 밸런스 조정 | 성장 이후의 목표 |

## 8. 검증

- 기존 검사 전부: 타입 검사, 빌드, E2E, UI 테스트, 전투 배치 비교.
- **빈 프로필 회귀**: `tests/equivalence/run.mjs`로 이전 빌드와 비교해 IDENTICAL.
- 새 E2E: 판 종료 후 엽전 보관, 능력치 구매, 다음 판에 반영, 영웅 해금, 조각 획득과 전수 조건 완화.
- 저장 형식 검사: 깨진 JSON, 이전 버전, 저장 불가 환경에서 기본값으로 동작.
- 밸런스 봇에 프로필 프리셋(없음, 중간, 최대)을 넣어 관문별 시간과 완주율 비교.

## 9. 위험과 대응

| 위험 | 대응 |
|---|---|
| 단일 HTML 파일을 폰에서 직접 열면 저장이 이어지지 않을 수 있다 (빌드마다 파일이 다르고, 여는 방식에 따라 저장소가 달라진다) | 저장 코드 내보내기·가져오기. 계속 이어서 테스트하려면 고정 주소에 올리는 방법(예: GitHub Pages)을 따로 정한다 |
| 메타 수치가 시드 재현을 깨뜨림 | 판 시작 스냅샷만 읽는다. 빈 프로필 회귀 검사 |
| 엽전을 아끼느라 판 안의 객잔을 안 쓰게 됨 | 객잔 가격은 낮게 유지하고, 능력치 가격으로 조절한다. 봇과 플레이로 확인 |
| 정보가 다시 과해짐 | 화면마다 한 가지 질문, "지금 → 다음 단계"만 표시, 기술 표기 규칙 재사용 |
| 시작 영웅이 2명으로 줄어 처음 판이 답답함 | 첫 해금(철혈)을 한두 판 안에 얻게 한다 |
| 성장 후 난이도 붕괴 | M4 난이도 단계. 그 전까지는 측정만 |

## 10. 정해야 할 것

1. **영웅 획득 방식**: 조건 해금(추천)인가, 뽑기인가. 뽑기라면 엽전과 다른 재화가 하나 더 필요하다.
2. **시작 영웅**: 풍운객 + 비천(추천)인가, 지금 기본 편대인 풍운객 + 철혈인가.
3. **탈락 시 엽전**: 전액 보관(추천)인가, 일부만인가.
4. **저장 이어가기**: 저장 코드 방식으로 충분한가, 고정 주소에 올릴 것인가.
5. **난이도 단계(M4)**를 이번 범위에 넣을 것인가.
